# 前端产品与设计蓝图

## 1. 设计定位

目标不是做一个“像 ERP 的后台”，而是把 ERPNext 的清晰表单、单据状态、紧凑列表和活动时间线，转化为一个以决策为中心的 Agent 工作台。

界面应同时让人感到：

- 像成熟业务软件一样可信、稳定、可追溯。
- 像 AI 产品一样能解释、推演和主动推进任务。
- 对门店和采购人员足够直观，不要求理解模型术语。

参考 ERPNext 的交互原则，但采用原创品牌、布局细节、组件样式和图标，避免复制其源码、Logo、商标或逐像素界面。

## 2. 信息架构

```text
库存现金智能体
├── 今日工作台
│   ├── 资金占用总览
│   ├── 今日 Agent 结论
│   ├── 待我审批
│   └── 执行效果
├── 风险中心
│   ├── 滞销风险
│   ├── 近效期风险
│   ├── 采购敞口
│   └── 缺货与安全库存
├── 行动方案
│   ├── 调拨方案
│   ├── 促销方案
│   ├── 退供方案
│   └── 采购调整
├── 现金模拟
├── 执行追踪
├── Agent 运行记录
└── 设置
    ├── 数据连接
    ├── 风险规则
    ├── 审批流程
    ├── 门店与区域
    └── 角色权限
```

导航按用户目标组织，不照搬 ERP 的销售、采购、库存模块划分。

## 3. 页面结构

### 3.1 全局框架

桌面端采用：

- 左侧 240px 主导航：品牌、工作区、常用入口和设置。
- 顶部 56px 命令栏：面包屑、全局搜索、日期/组织范围、通知和用户。
- 主内容区：最大内容宽度 1440px，表格页可铺满。
- 右侧情境抽屉：显示 Agent 解释、证据或审批，不强迫用户跳页。

在 1024px 以下，左侧栏收起为图标栏；移动端首期只支持审批、查看和执行确认，不承诺完整配置能力。

### 3.2 页面路由

| 路由 | 页面目标 | 主操作 |
|---|---|---|
| `/workspace` | 今日库存现金指挥台 | 开始分析、查看待审批 |
| `/risks` | 筛选、排序和批量处理风险 | 生成方案、指派负责人 |
| `/risks/[id]` | 查看风险事实、诊断和证据 | 接受诊断、生成新方案 |
| `/proposals` | 统一管理候选方案与审批状态 | 提交审批、批量比较 |
| `/proposals/[id]` | 单据式查看收益、成本、约束和时间线 | 批准、驳回、要求修改 |
| `/transfers/[id]` | 查看调拨路线、批次和执行状态 | 生成调拨单、确认收货 |
| `/scenarios` | 用自然语言提出资金目标 | 运行模拟、保存情景 |
| `/executions` | 追踪外部执行及异常 | 重试、标记完成 |
| `/agent-runs/[id]` | 查看 Agent 节点、工具和证据 | 回放、导出调试包 |
| `/settings/connectors` | 配置数据源和字段映射 | 测试连接、同步 |

## 4. 三类核心页面模板

### 4.1 Workspace：决策驾驶舱

```text
┌─────────────────────────────────────────────────────────────┐
│ 早上好，王经理       数据截至 08:05       [运行今日分析]     │
├────────────┬────────────┬────────────┬──────────────────────┤
│ 资金占用   │ 可释放金额 │ 近效期风险 │ 待审批               │
│ ¥386,240   │ ¥217,800   │ ¥72,600    │ 8                    │
├───────────────────────────────────┬─────────────────────────┤
│ Agent 今日结论                    │ 30 天现金测算进度       │
│ 事实、待核查因素与待审批方案      │ 目标、缺口与现金事件     │
├───────────────────────────────────┼─────────────────────────┤
│ 建议优先队列                      │ 待我审批                │
│ 收益、风险、期限、负责人          │ 单据号、金额、剩余时间   │
├───────────────────────────────────┴─────────────────────────┤
│ 执行效果：预计 vs 实际、报损减少、缺货变化                  │
└─────────────────────────────────────────────────────────────┘
```

首屏必须先给结论与行动，不能先给一排没有上下文的图表。

### 4.2 List：ERPNext 风格的高效列表

列表页包含：

- 页面标题、保存的视图、主要动作按钮。
- 轻量筛选条：门店、品类、风险类型、负责人、状态和日期。
- 可排序表格；左侧固定商品/单据，右侧固定金额/操作。
- 行内状态点、证据等级、关注库存成本、预计净现金改善和截止时间。
- 多选后的批量操作栏。
- 点击行打开详情，快捷预览用右侧抽屉。

推荐默认列：风险/单据、门店、SKU、待核查因素、关注库存成本、建议动作、净现金改善口径、证据等级、状态、负责人。

### 4.3 Form：单据详情页

```text
┌──────────────────────────────────────────────────────────────┐
│ ← 调拨建议 TR-2026-0182      待审批      [驳回] [批准并执行] │
│ 创建于 08:14 · 证据：部分支持 · 数据快照 DS-0821           │
├──────────────────────────────────────────────────────────────┤
│ 摘要：从甲店调往乙店 40 件，预计净释放 ¥3,114               │
├──────────────────────────────┬───────────────────────────────┤
│ 单据字段                     │ 收益与风险                    │
│ 商品 / 批次 / 调出 / 调入    │ 净现金改善 / 成本 / 缺货概率  │
│ 数量 / 运输 / 截止日期        │ 基准对比 / 关键约束           │
├──────────────────────────────┴───────────────────────────────┤
│ [诊断依据] [方案比较] [审批记录] [执行结果]                  │
├──────────────────────────────────────────────────────────────┤
│ 时间线：Agent 分析 → 规则校验 → 人工意见 → ERP 回执          │
└──────────────────────────────────────────────────────────────┘
```

页面顶部保持单据感；Agent 的思考不作为“神秘聊天内容”展示，而被拆成事实、证据、假设、约束和结论。

本轮已经落地的核查控件保持三步：描述发现、选择核实方式、确认整理结果。原文、客户时区和事实版本必须能从页面回到 API；草稿确认前显示“待确认”，不能改变方案或案例检索。

## 5. Agent 交互模式

### 5.1 Agent 不是悬浮聊天框

主要 Agent 入口有三种：

1. **今日结论卡：** 主动报告最重要的风险和行动。
2. **页面内建议：** 在风险/方案详情中解释“为什么”和“还有什么选择”。
3. **现金模拟：** 自然语言输入目标，例如“30 天释放 20 万，缺货风险不得超过 5%”。

全局聊天只作为辅助查询，不承担审批或执行主流程。

### 5.2 Agent 运行可视化

运行过程中展示业务阶段，而不是暴露模型思维链：

```text
✓ 读取当前数据快照
✓ 识别规则命中的风险候选
✓ 完成跨店供需匹配
● 正在计算调拨约束…
○ 生成采购调整组合
○ 校验方案并形成审批单
```

完成后展示使用了哪些数据、规则和工具，以及哪些信息缺失；不展示隐藏推理文本。

### 5.3 证据组件

每条结论都能展开证据：

- 指标值、对比基准和时间范围。
- 来源系统、同步时间和数据质量。
- 可点击的关联销售、库存、采购和批次记录。
- 证据等级、支持引用、缺项和冲突；不展示未经规则支持的数字置信度。

金额卡片同时显示口径和完整性：库存成本金额、预计净现金改善、预计避免报损不能合并成一个“释放现金”。数据快照、合成样例和外部回执状态必须有来源标签。

## 6. 视觉设计系统

### 6.1 品牌方向

关键词：克制、精确、可信、有温度。以药房绿色表达健康，以深墨色表达金融决策的严谨。

建议色板：

| Token | 值 | 用途 |
|---|---|---|
| `--brand-600` | `#16775B` | 主按钮、选中态、关键链接 |
| `--brand-50` | `#ECF8F3` | Agent 结论和成功背景 |
| `--ink-950` | `#15201D` | 主文字和导航 |
| `--ink-600` | `#5C6B66` | 次级文字 |
| `--surface` | `#FFFFFF` | 卡片和表单 |
| `--canvas` | `#F6F8F7` | 页面背景 |
| `--line` | `#DEE5E2` | 边框与分隔线 |
| `--warning` | `#B7791F` | 近效期和需关注 |
| `--danger` | `#C2413B` | 高风险、驳回和异常 |
| `--info` | `#3568A8` | 执行中、外部同步 |

颜色只作为辅助，状态必须同时有文字或图标，不能只靠红绿区分。

### 6.2 字体与数字

- 中文：系统字体优先，产品化时可使用思源黑体/Noto Sans SC。
- 西文和数字：Inter 或 Geist Sans。
- 金额和表格数字启用等宽数字特性，右对齐。
- 页面标题 24/32，区块标题 16/24，正文 14/22，表格 13/20。

### 6.3 密度与形状

- 8px 间距基准；常见间距 8/12/16/24/32。
- 卡片圆角 10px，输入框和按钮 8px，状态胶囊 999px。
- 阴影极少使用，主要依赖背景、边框和留白分层。
- 默认表格行高 44px，可切换舒适模式 52px。

### 6.4 状态语义

| 状态 | 视觉 | 文案示例 |
|---|---|---|
| 草稿 | 中性灰点 | 草稿 |
| 待审批 | 琥珀色点 | 等待区域经理审批 |
| 已批准 | 绿色点 | 已批准 |
| 执行中 | 蓝色旋转/进度 | ERP 草稿已创建 |
| 已完成 | 深绿色勾 | 已收货 |
| 异常/驳回 | 红色点 | 库存已变化，需重算 |

## 7. 业务组件库

在通用组件之上建立业务组件，避免每个页面重复拼装：

- `MoneyMetricCard`：金额、环比、口径和钻取。
- `RiskBadge`：风险级别、原因和截止时间。
- `DocumentStatus`：单据状态及允许的下一步动作。
- `EvidencePanel`：证据、来源、时间和质量。
- `AgentRunStepper`：业务阶段进度及错误恢复。
- `CashReleaseWaterfall`：从占用金额到净释放的瀑布图。
- `ScenarioComparison`：多方案收益、风险、成本对比。
- `TransferRoute`：调出店、运输、调入店、数量和效期。
- `ApprovalTimeline`：Agent、人工和外部系统的统一事件流。
- `DataFreshness`：同步时间和数据质量提示。
- `ImpactGuardrail`：安全库存、缺货概率、毛利等硬约束。

## 8. 前端工程架构

推荐 Next.js App Router + TypeScript：

```text
apps/web/src/
├── app/
│   ├── (auth)/
│   ├── (workspace)/
│   │   ├── workspace/
│   │   ├── risks/
│   │   ├── proposals/
│   │   ├── scenarios/
│   │   ├── executions/
│   │   └── settings/
│   └── api/                  # 仅 BFF 场景，不放核心业务
├── features/
│   ├── risk/
│   ├── proposal/
│   ├── transfer/
│   ├── scenario/
│   ├── approval/
│   └── agent-run/
├── components/
│   ├── ui/                   # 基础组件
│   ├── business/             # 业务组件
│   └── charts/
├── lib/
│   ├── api-client/
│   ├── auth/
│   ├── permissions/
│   └── formatting/
└── styles/
    └── tokens.css
```

工程约束：

- API 类型由 OpenAPI 自动生成，前后端不手写重复 DTO。
- 服务端组件负责初始读取；筛选、批量选择和实时进度由客户端组件承担。
- URL 保存筛选、排序和分页，列表可分享、可回退。
- 权限必须由后端最终裁决，前端只做操作提示与隐藏。
- 金额、数量、时区和日期统一格式化，禁止组件各自处理。
- 图表必须能回到明细表；关键数字必须可解释口径。

## 9. 黑客松优先实现的 5 个界面

1. 今日工作台：一句话结论、关注库存成本、净现金改善完整性和待审批。
2. 风险详情：某商品为什么滞销、证据是什么、可选动作有哪些。
3. 调拨方案：从哪里到哪里、多少件、为什么安全、释放多少钱。
4. 审批单：方案摘要、预计收益、风险、批准/驳回及时间线。
5. 现金模拟：“30 天释放 20 万”的对话输入和三方案比较。

现有静态 Demo 可以继续承担第 1 个界面的展示；后续 Next.js 版本优先把这五个故事串成一条可交互主流程。
