# 朱的下一轮工作与零售产品能力

本文基于当前v1.2前端和实际后端，区分本轮工作与后续计划。后端、根API_CONTRACT.md由魏在lanyangyang维护；朱的前端、评测和文档在zmj维护。模型、跨进程事务、原子版本校验、真实经营数据与ERP执行仍分别验证；已有测试通过不等于商业效果成立。

## 本轮：把已生成的任务接回具体门店工作

本轮已实现“今日待办定位 → 核对任务 → 保存人工回执”的前端流程改进，并完善移动端键盘导航和跨平台测试。具体测试数量、运行环境和CI结果统一以[验证记录](VALIDATION_RESULT.md)为准；以下“已实现”指代码具备的行为，不代表已经测得节省时间或客户收益。

- 任务业务上下文：仅当proposal_id和proposal_version与已读取方案及其保存版本一致时，显示保存输入中的商品、门店和工作台。旧版本、重复编号或缺项明确未知，不套用新版事实。
- 当前分类内搜索：当前方案可按服务端已显示的标题、商品和门店检索，即使初始样例没有保存输入也能找到；任务仅按其精确版本的保存身份及方案号、任务号检索。显示分类总数和匹配数，保留服务顺序，不改金额、状态或服务端数据。
- 审批后跟进：只有同一方案、同一当前版本的任务才替代该版本的“生成任务”入口。旧版本任务已完成，不会让新版本已审批方案从跟进列表消失。
- 人工回执缓存与冲突核对：按任务独立保留当前页面内未保存的进度和回执号，支持搜索、分类切换、页面切换后继续填写或单独放弃。保存前重新读取服务记录，遇到状态、回执或关联版本变化时保留输入并要求核对；只有返回任务、方案版本、进度和回执都匹配时才清除相应编辑。读取失败、任务暂时缺失或保存失败不会伪造成功。缓存不跨浏览器刷新或关闭持久化，离开前会提示未保存；提交前核对仍不能代替服务端原子版本校验。
- 移动端键盘导航：关闭时侧栏退出键盘焦点范围；打开时焦点留在导航内，Tab与Shift+Tab循环，Escape关闭并恢复焦点。选择页面后聚焦正文，屏幕宽度变化时解除不适用的焦点限制。
- Windows文件身份测试：启动器数据库测试按实际文件身份判断独立演示库与日常库的关系，避免仅按路径字符串的不同写法误判；继续验证日常数据受保护，不放宽隔离要求。

对应实现为assets/js/queue-view.mjs、task-receipts.mjs、navigation.mjs及app.js；模块、浏览器和启动器测试分别验证关联、操作与文件隔离。主文件由同一前端负责人协调修改，避免同时写入。以上均不需要新增模型调用，不向他人发送通知，不自动执行业务。

## 两项待小规模试用的探索

**P2：带证据的门店案例复盘。** 从已有门店反馈、人工确认和执行记录整理历史案例，帮助下次核查时找到类似问题及需要追问的事项。朱负责案例检索、原文证据和时间范围的呈现；魏负责授权范围内的历史读取、证据版本、适用条件和有效性。先用明确字段、标签与关键词检索，不需要新增模型调用；过期方案保留历史标识，不能直接复制数量、价格或审批结论到当前方案。试用前选少量已授权案例，衡量找到证据和完成核查的时间、重复追问次数及过期证据误用，尚无历史服务时只做脱敏样例预览。

**P2：同一门店或线路的一张交接清单。** 把符合条件的可执行事项组织成一张清单，减少操作人员在既有系统中逐张查找和重复录入。朱复用现有导出能力，先做选择、来源方案及版本、逐项内容的预览；魏定义批次占用、线路、时限、数量单位与合单约束，并返回允许组合的结果。约束未冻结前，前端只能列示独立事项，不能重算合计业务数量、合并批次或宣称已经生成可执行合单；保留各项审批和执行身份，不做批量审批。选择、预览和确定性约束校验不需要新增模型调用。

两项探索先各选少量真实授权案例试用，在同等输入和任务要求下记录核对时间、跨系统重复录入时间、人工更正与未完成原因，再决定是否产品化。合成样例可验证交互，不能证明真实效率或ROI；已有五个Agent不重复改名计作新功能。

## 文件边界与协作方式

- 朱：app.js、styles.css、assets/js/、前端浏览器与模块测试、sample-data/evaluation/、评测脚本和朱维护的交付文档。新展示逻辑复用现有请求、校验、格式化与状态机制。
- 魏：backend/、数据库、真实模型适配、工具计算、权限/事务、根API_CONTRACT.md及后端回归。朱提交可复现输入和预期边界，不在前端补算后端结果。
- 共同对接：每项变更先写输入、输出、缺项、身份/版本、失败和单位口径；由魏修改契约，朱新增消费该契约的页面与测试。一个文件同一时间只有一个修改负责人，集成时保留双方提交。
- 演示、模型评测与商业实测分别记录。不得把合成语料、固定回复、一次成功录像或页面测试数量作为真实模型效果和客户收益。

本轮暂不增加自动群发、批量审批、通用聊天入口、全自动ERP执行或五个Agent之间反复对话。先验证上述已有流程中的查找、核对和交接是否更省事，再决定扩展范围。
