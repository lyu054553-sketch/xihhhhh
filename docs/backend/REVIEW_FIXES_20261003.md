### 已有库存数据库兼容

新指纹采用版本 2，返回 semantic_sha256、fingerprint_version。对没有语义指纹的旧文件快照，从不可变源明细识别相同记录，不读取被人工纠正后的风险事实来判断重复。复用时保留旧 snapshot_id、content_sha256、风险 ID 和确认记录，仅补充指纹元数据，不改变 created_at。多个历史匹配记录保留原记录，不合并、不删除；选择最新匹配记录。源明细有无法恢复的精度或缺损时不冒险判为相同。

改变日期或实际记录内容会创建新快照，失效旧未执行方案。重复旧文件不会重新激活历史快照。新旧快照仍使用既有存储结构；此前 REAL 金额存储的精度限制不由本批扩大迁移。

### 旧模拟接口边界

`/api/v1/scenarios/simulate` 定义为 future_actions：已完成动作不再贡献新动作节省，人工完成回执也不会自动释放订单或库存占用。它不承担历史收益归因，不与 `/api/v1/retail/simulate` 的独立演示数据混用。

缺少快照日期返回 409 missing_planning_date；规划期间快照变化返回 409 stale_snapshot，避免用旧窗口解释新候选。选中候选附带快照、事实版本、方案版本和剩余资源，供调用方核对。延期付款进入更长窗口后不再产生该窗口的现金改善；日期缺失时现金保持未知。未知销售及收款日期的调拨／效期收益继续保持未知。

本批保留原有贪心求解加组合校验。共享资源不足时可能阻断整个建议组合，不保证自动寻找另一个可行组合或证明最优解。真实文件尚未提供采购订单、配送规则和付款计划时，也不会虚构可执行候选。
