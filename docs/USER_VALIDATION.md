# 用户验证与离线对照评测

当前准备的是采集方法、空表和汇总工具。尚未开展真实用户访谈、商业收益验证或真实模型评测，不以合成案例替代这些证据。工具不连接模型、后端或客户系统。

## 先确认一个具体岗位与任务

本轮建议验证“连锁零售运营人员收到门店反馈后，核对库存风险并形成可审批方案”这一条流程。行业、岗位和付费方需要由受访者确认，不预设门店员工就是购买决策人。

访谈由朱组织记录，魏协助确认数据与计算口径。联系真实用户、发送消息或共享数据应另行取得用户明确授权；此文档本身不安排或发送访谈邀请。

每次访谈记录以下内容，未取得的信息保持空缺：

| 记录项 | 需要采集的事实 |
| --- | --- |
| 访谈编号、日期、岗位 | 使用匿名编号；不把姓名、手机号和客户明细放入公开仓库 |
| 最近一次真实案例 | 何时发生、谁发现、用了哪些表和系统、最后如何处理 |
| 当前操作过程 | 导出、核对、询问、审批、录入及等待分别用了多久 |
| 主要困难 | 缺失字段、单位混用、过期资料、重复录入、决策难点的具体例子 |
| 现有替代方案 | ERP、Excel、人工经验、GPT各自如何使用，有何限制 |
| 业务责任与付费 | 谁使用、谁审批、谁承担错误损失、谁有预算及购买权限 |
| 可用数据 | 是否有授权的脱敏样例、时间范围、已知缺项和更新时间 |
| 验收条件 | 什么结果能用、什么错误不能接受、是否愿意参与只读试用 |
| 引用许可与证据 | 哪些原话可公开引用，录音/笔记保存在何处 |

保留受访者反对意见。“感觉省时间”“愿意试用”和真实付费不是同一证据。没有真实观察，不填写节省比例、年收益或付费意愿人数。

## 公平对照的操作步骤

1. 先冻结一组任务案例。每个 case_id 对应同一任务、同一数据快照、同一业务约束和同一验收标准，允许出现缺项、冲突及“暂不采取行动”的合理结果。
2. 比较 human_gpt 与 system。基线使用熟悉任务的人员和可正常使用的 GPT，给予相同资料、业务规则及计算工具，不能只给基线一张报表而给系统额外信息。
3. 记录实验上下文：操作者经验、模型及版本、提示词版本、允许工具、数据摘要、系统提交号、网络环境和评审标准。两组条件有差异必须披露。
4. 交替或随机安排两组顺序，尽量避免先做一组后直接照抄结果。使用同一操作者时记录熟悉效应；不同操作者时记录经验差异。
5. 从开始处理计时，到交付可核对结果或明确停止为止。等待模型、核对、人工修改和重试都计入 elapsed_seconds；人工实际工作时间另记 human_seconds。
6. 按同一标准评审结果，记录 accepted、revision_needed、rejected 或 not_assessed。completed只表示流程完成，不代表结果合格。
7. 业务执行单独记录：未执行、仅草稿、实际执行、执行失败或结果未知。只有真实回执才能标为 performed；模拟、审批和创建任务都不是实际执行。
8. 保存成功、失败、放弃和未完成案例。每个案例每种方法一行，重试累积在该行，不能只保留最后一次成功的时间和费用。

一次性字段映射、培训、接入和维护成本要单独记录，并说明是否分摊到案例。不得因为暂未测到这部分成本，就声称采用系统没有额外工作量。

## 填写对照 CSV

模板为 [workflow-comparison.csv](../sample-data/evaluation/workflow-comparison.csv)，仅有表头，没有伪造的实测行。复制到私有评测目录再填写。[workflow-schema.json](../sample-data/evaluation/workflow-schema.json)规定列名、范围与枚举；它不是 v1.2 业务接口或模型响应协议。

| 列 | 填写规则 |
| --- | --- |
| case_id | 同条件案例编号；同编号分别填写两种方法 |
| arm | human_gpt 或 system |
| status | not_run / in_progress / completed / failed / abandoned |
| review_outcome | not_assessed / accepted / revision_needed / rejected |
| elapsed_seconds | 全部实际测量耗时；已完成但未计时仍留空，不改写流程状态 |
| human_seconds | 实际人工秒数；未测留空 |
| human_edits | 按实验前冻结的定义，计人工改事实、参数或建议的次数；未测留空 |
| execution_status | not_applicable / not_started / draft_only / performed / failed / unknown |
| model_cost_cny | 本案例所有请求、失败和重试的模型成本 |
| labor_cost_cny | 按预先说明的人工成本口径记录，不由脚本猜测时薪 |
| other_cost_cny | 其他实际成本；分摊、汇率及费用口径写入notes |
| evidence_ref | 脱敏计时、操作、计费及评审记录的引用，有测量或已评审时必填 |
| execution_evidence_ref | performed必填真实执行回执引用 |
| notes | 条件差异、计费依据、异常及停止原因 |

数字留空表示未测，不填“未知”、NaN或虚构的0。只有确实测到零或明确没有该项费用才填0。费用统一折算人民币元，允许最多六位小数以保留单次模型调用的小额费用；换汇与计费来源须记录。该精度与业务API的商品金额精度是不同用途。

not_run行只登记待测案例，数字全部留空、review_outcome=not_assessed、execution_status=not_started。实际完成业务但没有计时证据时，保留completed并留空时间，说明缺测；不补造时间，也不把已完成流程改写成未完成。

~~~powershell
python scripts/evaluate_workflow.py --input sample-data/evaluation/workflow-comparison.csv
python scripts/evaluate_workflow.py --input C:\评测\observations.csv --output C:\评测\summary.json
python -m unittest tests.test_workflow_evaluation -v
~~~

空模板输出 no_observations，分布和成本为 null，不会生成“系统更快”的结论。重复case_id/arm、非法数值、非法状态、缺列和无证据的测量会报错，退出码为2；合法输入退出码为0。

## 如何解释汇总

- registered_pairs是两组都有记录的案例数；completed_pairs要求两组都完成；timed_completed_pairs进一步要求双方都有实际总耗时；accepted_pairs要求两组都完成且获人工接受。这些分母不能混用。
- 时间与修改次数仅在双方都测量了相应指标的完整案例内比较。不同指标可能有不同分母；差值固定为system减human_gpt，负耗时差表示本样本中系统更快。
- 每组仍保留全部状态、评审和执行计数，明确未配对、失败、放弃及缺测。不能只摘取accepted子集作为总体效果。
- terminal_cost_comparison只比较双方都终止且三项成本都已知的配对案例，包括失败和放弃。每组的terminal_complete_cost_total_cny也只统计这种成本完整的终止行。
- known_cost_components仅累加该项已知费用，可能包括进行中的请求；不是完整总成本，不能将未测人工成本视为0。
- 中位数和p90采用样本排序后的线性插值；样本很小时p90仍只是描述值。脚本不做显著性检验、不推断因果，不自动算ROI或全年节省。
- 脚本记录证据引用，但不会验证引用真实性。证据需由双方人工复核。

采购减量、库存成本下降、内部调拨金额和现金到账必须分开。商业价值若要量化，应依据实际报损、毛利、运输、折扣、人力和实施成本，说明观察期和对照条件；不能把几个金额直接相加当收益。

## 门店反馈模型评测的准备

[store-feedback-reference.json](../sample-data/evaluation/store-feedback-reference.json)新增24条合成门店反馈，覆盖否定、推测、日期、非法日期、零值与未知、包装单位、多个门店/商品、多因素、条件退供和越权文字。它与既有采购情景24条语料用途不同，不修改现有生成数据包。

每条包含原文、标签和人工参考：

- facts：原文支持的陈述及连续证据片段；保留否定、单位和时间含义。原文陈述不等于业务事实已确认。
- uncertainties：缺项、矛盾、模糊、未确认或过时信息。
- follow_up_questions：可接受的澄清方向，不要求逐字一致。
- do_not_infer：不得猜测或冒充确定事实的结论。

参考标注仍待业务人员复核，evaluation_status=not_run，model和metrics为null。当前字段只是离线标注格式，**不是魏尚未冻结的AI响应Schema**。

魏完成接口后，再冻结响应到标注的映射、日期锚点、单位口径与判分规则；保留真实模型名称、请求编号、原始输出、校验错误、输入输出token、耗时及费用。分别统计字段准确、遗漏/多提取、缺项与否定保留、需要人工修改的案例和失败次数。没有模型运行前，本轮只校验语料结构与汇总工具，不报告模型效果。
