# 数据连接｜比赛版样例 ERP 接入设计

> 2026-10-04 v1.1。当前交付是一份零食连锁 ERP 样例数据已进入本系统、可查看、可用于同源库存分析的流程。采购订单也使用样例事实展示。比赛版不连接真实客户 ERP；此前讨论的实时事件推送、自动重算作为后续扩展。

## 1. 页面

沿用现有清新绿界面，导航名称为“数据连接”。主区域显示一张“零食仓 ERP”来源卡：

| 内容 | 展示规则 |
| --- | --- |
| 接入状态 | 只有样例场景成功保存到事实库且可查询时显示“已接入”，不可只写死在前端 |
| 数据时点 | 从事实记录和分析上下文读取库存截至时间、分析基准时间 |
| 覆盖范围 | 显示有完整业务数据的门店数／门店名录数、SKU 数、在库批次数和采购记录数 |
| 库存与采购预览 | 展示门店、商品、批次、库存数量和成本，以及采购单、订购／已收数量、金额和状态；数字与事实服务一致 |
| 模型配置状态 | 显示所选模型及文本／图片配置是否齐全；不显示密钥，也不把已配置写成调用成功 |
| 操作 | “查看接入数据”滚动到预览；“查看库存分析”进入读取同一场景事实的方案页面 |

比赛展示页隐藏库存表格上传与导入历史入口，不要求管理员上传或确认样例数据。原有页面结构、事件处理和文件导入 API 保留在代码中，由 `ENABLE_LEGACY_FILE_IMPORT` 开关控制挂载；比赛版设为 `false`。采购／退供材料的单张截图输入是另一条流程，继续保留。页面明确来源为样例数据，不展示虚构的第三方授权结果。

## 2. 系统架构

    零食连锁样例 XLSX
           ↓
    现有场景加载器（保留 retail-v2 数据集来源）
           ↓
    Store / SQLite + RetailFactService 正式事实
           ├── 数据连接只读接口 → 来源状态与库存预览
           └── 现有风险和方案接口 → 同一批库存分析

现有启动流程已把隔离的比赛场景导入 RetailFactService。新增的只读接口基于已保存的 S01 场景读取库存、门店、商品及采购记录，再计算来源卡和库存预览。接口失败时页面显示未接入，不把静态示例文案当作成功。连接状态和库存数量来自同一事实库；不会另建一套供页面展示的假库存。

本轮采用 GET /api/v1/hackathon/data-connections/erp 返回状态、数据时点、覆盖计数、库存与采购预览及不含密钥的模型配置状态。页面将样例数据呈现为“零食仓 ERP”来源，原始事实仍保留 `retail-v2` 标识。来源卡跳转已有方案决策页，不需要新增连接向导或外部账号授权。S01 主线维持 120 盒库存、调拨 80 盒、售出 64 盒的原有口径。

## 3. 当前与后续边界

本轮只完成一次样例接入及展示。既有业务回放照常使用场景时钟；ERP 新库存事件播放、服务端推送和新事件触发建议重算留到后续客户或比赛迭代。将来接真实 ERP 时替换来源读取层，再补授权与字段适配；事实、风险和方案读取层继续复用。

## 4. 完成条件

1. 后端未导入样例事实时，页面不显示“已接入”。
2. 成功导入后，页面的门店、SKU、批次、采购计数与事实库一致。
3. 库存预览中同一门店商品批次的数量，与方案页使用的 S01 事实一致。
4. 刷新页面后仍从后端读到相同的接入状态和库存预览。
5. 比赛页面不显示库存表格上传入口；原有导入前后端代码和单张业务材料识别入口仍保留。
