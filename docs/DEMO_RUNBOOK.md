# 五分钟演示与录像脚本

这是本地规则版本的演示方案。所有演示快照均为合成数据；结果是模拟测算，不能解释为客户 ROI。真实模型未接入，不演示“已经完成的 LLM 调用”。先排练全流程，录像保留真实交互和失败状态。

## 演示前

1. 按 README 安装依赖，执行 `.\start.ps1 -Check`，确认 `demo` 模式及项目外的独立演示库。
2. 执行 `.\start.ps1`，打开 `http://127.0.0.1:8000`，不要打开 `file://` 页面或真实实例。
3. 运行 README 中的测试和场景一致性检查，将实际输出写入提交说明。
4. 重演仅使用本实例的演示重置入口，不手工删除数据库，不向真实实例调用重置接口。
5. 浏览器约 1440 × 900、100% 缩放；确认数据源和规则模式标签，录制时避开真实文件与凭证。

## 五分钟时间线

| 时间 | 操作 | 解说 |
| --- | --- | --- |
| 0:00–0:30 | 总览；指出数据源和运行模式 | “合成数据上的库存决策工作台。库存成本、避免报损和现金改善分别显示。当前使用确定性工具，真实模型由另一位同学接入。” |
| 0:30–1:15 | 滞销诊断，选择西湖文三店钙维生素 D 示例，查看事实和缺项 | “销量异常可以计算；原因要核查陈列、缺货等证据。” |
| 1:15–2:00 | 发起核查；提交下方反馈，查看草稿，人工确认 | “原文先成为待确认草稿。核对后保存反馈版本，旧方案重新评估。” |
| 2:00–3:00 | 调拨数量设为 `100` 重算看阻断，再设为 `40` 重算 | “数量、接收能力、效期与费用由后端校验；输入改变后不能沿用旧结果。” |
| 3:00–3:45 | 保存 → 提交审批 → 人工审批 → 生成执行任务 | “这是执行草稿，没有向 ERP 发货；编号和状态由后端返回。” |
| 3:45–4:25 | 近效期、采购分别重算；采购形成草稿后打开现金模拟 | “处置数量要守恒；采购区分在途和未执行量；模拟只组合已计算草稿。” |
| 4:25–5:00 | 模拟 `20` 万、`30` 天；展示断网错误与重试 | “缺口如实显示，内部调拨不是回款。接口失败不会填一组成功数字。” |

演示反馈：

> 门店现场核查：上个月有20天商品放在仓库，没有摆上货架，今天已补上。暂未取得缺货台账，销量恢复情况待观察。

必须把结构化内容与原文一起核对。当前后端采用固定因素模板和日期规则；返回不符时不确认，不声称模型已理解。“40 件可行”仅适用于内置默认门店及参数；切换门店后以实际校验为准。

## 扩展入口与故障演示

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 近效期冲突 | 内置批次调拨 `40`、促销 `90` 后重算 | 超过库存时约束错误，不能保存可执行方案 |
| 采购付款 | 切换减量、延期到货、延期付款后重算 | 库存、在途、未执行采购及付款分列，未支持假设保持待确认 |
| 现金缺口 | 目标高于已计算草稿的现金改善额 | 显示 `gap` 和缺项，不虚构动作；排除动作后重算 |
| API 中断 | DevTools Network 设 Offline 后刷新；恢复 Online 并重试 | 错误明确，不能切换为演示成功数据 |
| 输入变更 | 计算后改数量，不重算 | 旧结果失效，保存/审批不可沿用旧输入 |
| 快速切换 | 快速选择不同风险/门店 | 标题、证据及表单属于最后一次选择 |
| 空列表 | 浏览器测试拦截列表返回 `items: []` | 空状态，不能填内置案例或风险 |
| 缺字段 | 导入生成场景中缺字段 CSV | 字段错误被保留；校验通过也不称分析快照已更新 |
| 移动端 | 390 × 844 打开五个入口 | 数据源、错误和主要按钮可见；表格可横向滚动 |

模型超时、限流和非法 JSON 尚无真实接口可复现；测试夹具只能证明故障展示，必须注明“故障注入”。

## 视频分镜

推荐约五分钟连续录屏，按时间线操作并口述。短时无旁白的浏览器自动录像可作为测试证据，交付时应标为“自动化流程录像”。

本分支已提供[自动化流程录像](demo-recording/demo-flow.webm)和[执行草稿截图](demo-recording/demo-flow.png)：使用合成数据、临时数据库和真实本地 API，记录调拨测算、审批与创建执行草稿。这份无旁白的操作实录不代表 ERP 已执行，也不替代五分钟讲解片。

自动录制主链的方法（先安装开发依赖及 Playwright 浏览器）：

```powershell
$env:FRONTEND_TEST_ARTIFACTS = 'docs/demo-recording'
.\.venv\Scripts\python.exe -m unittest tests.test_frontend_browser.FrontendBrowserTests.test_transfer_approval_creates_execution_draft_without_external_completion -v
Remove-Item Env:FRONTEND_TEST_ARTIFACTS
```

测试使用临时数据库，结束后在指定目录保存 `demo-flow.webm` 和 `demo-flow.png`。这是无旁白的自动化操作录像；五分钟讲解使用下方分镜和 PPT 讲稿录制。测试类名与最新命令以[测试说明](../tests/README.md)为准。

| 镜头 | 画面 | 旁白/字幕 |
| --- | --- | --- |
| 1 | PPT 第 1 页 → 总览 | 库存决策从事实走向可审批的方案；常驻“合成数据 / 规则模式” |
| 2 | 风险与证据 | 异常和原因分别判断，证据不足显示缺项 |

不要隐藏报错，或拼接不同快照伪装成一次成功运行。倍率、金额与改善比例仅解释为当前合成场景输出。

## 答辩

**五个 Agent 是真实 AI 吗？** 当前是五个专业入口和后端确定性工具；真实模型、结构化校验和运行契约仍待接入。这里演示输入、证据、工具结果、人审和异常。

**为什么不用模型直接算钱、改库存？** 数量、现金口径与状态流转需要可重算和审计。未来模型负责理解、解释和工具编排，后端保持约束与计算的责任。

**已经为客户创造多少收益？** 当前没有真实客户收益结论。库存压降、避免报损和实际回款不同，合成场景金额不能相加作为 ROI。

**现在能上线吗？** 还需后端重置防护、受控静态资源、事务与版本冲突、鉴权、真实模型和 ERP 连接器；前端禁用按钮不能替代这些保证。

**为什么沿用原生前端？** 现有工作台有完整业务结构，优先整理状态和请求生命周期，不引入第二套应用或重复计算逻辑。
