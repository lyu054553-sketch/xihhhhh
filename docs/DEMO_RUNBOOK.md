# 货不压钱 · v1.2 五分钟演示

演示使用本地实际 FastAPI 后端与合成零食数据。业务计算由程序完成，当前没有模型调用。执行只生成本地待执行任务，人工状态登记不代表外部 ERP 已由系统操作。

当前已复现后端并发读取 500，完整联调未通过。以下为目标演示顺序；现场发生错误时应展示实际错误并说明待修复项，不能用成功录像冒充当次接口成功。录像记录的是此前一次成功流程。

## 演示前

1. 按 [README](../README.md) 安装依赖并运行 start.ps1，确认启动器输出的前端地址。
2. 核对页面的合成来源、日期及缺项，不把旧数据库中的方案状态当成新演示状态。使用独立演示数据库；不要重置用户数据。
3. 运行 python sample-data/generate.py --check，参考[验证记录](VALIDATION_RESULT.md)确认当前测试范围。
4. 先熟悉西湖文三店“每日坚果礼盒750g”的风险与调拨入口；所有金额以本次响应为准。
5. 准备好一条原始门店反馈，强调结构化草稿需要人工核对。不要用真实个人或客户资料录屏。

## 五分钟顺序

| 时间 | 操作 | 说明 |
| --- | --- | --- |
| 0:00—0:40 | 打开经营总览，查看四项金额与门店关注事项 | 账户、库存成本、风险成本和付款计划分别计算；合成数据不代表客户收益 |
| 0:40—1:20 | 点击商品进入风险详情，核对事实、证据及缺项 | 销售差异是观察，原因需门店核查；不凭报表认定未上架导致滞销 |
| 1:20—2:20 | 进入跨店调拨，修改数量，重新计算 | 改动后旧测算失效；展示两店库存、约束与费用；无效方案不能保存 |
| 2:20—3:20 | 保存方案、提交；今日待办人工审批，生成任务 | 保存是草稿，审批不是执行；任务仍为待外部执行 |
| 3:20—4:25 | 采购情景填14天、减量20%，先预览再确认 | 当前仅支持减少可调整采购；结果一起看采购支出、期末库存和缺货风险 |
| 4:25—5:00 | 展示一处约束失败或资料缺项，交代下一步 | 不用演示数字覆盖真实缺项；并发版本、模型和ERP仍待接入 |

审批前核对实际方案内容、版本与来源。若在其他页面改了输入，先重新计算并保存，再检查当前待审批方案，不能演示为系统已经解决所有并发冲突。

## 可选异常演示

- 调拨数量改得超过可调上限，运行计算；应显示服务端约束错误，保存不可用。
- 采购预览出现后再改比例；旧预览消失，必须重新确认。
- 真实资料不足或空租户应出现 null、空表及 unavailable，不能填入合成金额。
- 服务不可达时保留当前输入；先刷新核对写入结果，避免重复提交。

不要为演示故障结束他人的服务。自动化测试在自己的临时数据库与端口中执行异常用例。
