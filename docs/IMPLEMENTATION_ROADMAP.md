# 实施路线与验收标准

> 历史规划：以下包含旧版执行闭环及远期能力；当前开发范围以 [魏的 v0.3 契约](API_CONTRACT.md) 为准。当前任务和待对接事项见 [朱的交付清单](ZHU_DELIVERY.md)。

## 1. 总体策略

用一条真实且闭环的业务故事参加黑客松，再逐步扩展成产品。不要在首期同时建设五套自治 Agent、复杂微服务和所有 ERP 连接器。

建议演示主线：

```text
导入门店数据
→ 发现关注库存成本，并分开展示现金口径
→ 打开一个高优先级 SKU 查看原因证据
→ Agent 生成调拨 + 停采 + 促销组合
→ 对比现金释放和缺货风险
→ 负责人批准
→ 生成调拨单和采购调整建议
→ 在追踪页区分预计、人工确认、外部回执和观察结果
```

## 2. Phase 0：黑客松 Demo（当前已升级为 V1.1 本地闭环）

周期：3–7 天。

### 范围

- 使用脱敏样例数据或固定 Excel 模板。
- 跑通一个滞销诊断、一个跨店调拨、一个近效期促销和一个采购暂停案例。
- 数量和资金释放由真实公式计算，不写死在文案中。
- Agent 输出严格 JSON，再渲染为页面结论。
- 审批后生成可下载的调拨单/建议单，不直接写真实 ERP。
- 保存一次运行日志，演示“用了什么证据和工具”。

### 验收

- 从本地样例读取到方案生成不超过 60 秒。
- 每个建议都能追溯到输入数据和计算口径。
- 改变库存或销量后，建议数量和金额会随之变化。
- 任何外部动作在用户确认前不会执行。
- 断网或模型不可用时，确定性指标和已有方案仍可打开。

本轮已实际完成：FastAPI + SQLite 本地数据层、金额口径分离、核查反馈确认、方案版本失效、审批/执行幂等、统一情景模拟、案例持久化边界和 AC01—AC26 测试。详见 [本轮实施结果与 AC 报告](./IMPLEMENTATION_RESULT.md)。

## 3. Phase 1：可试点 MVP

周期：4–8 周。

### 建设内容（后续）

- Next.js 工作台、风险列表、方案单据、审批和执行追踪。
- FastAPI + PostgreSQL 业务后端。
- Excel/CSV 导入、字段映射、数据质量报告。
- LangGraph 总控与五个专业节点的第一版。
- 周转、效期、资金占用和采购敞口指标。
- OR-Tools 跨店调拨求解器。
- 企业微信/邮件通知或导出文件。
- RBAC、租户隔离、审计日志和决策快照。

### 验收

- 可承载一个客户、30–100 家门店、1–5 万 SKU 的日批分析。
- 同一输入和规则版本的确定性计算结果一致。
- 方案审批、驳回、改版、执行和完成都有时间线。
- 调拨方案不会突破安全库存和批次效期硬约束。
- 失败任务可重试且不会重复创建外部单据。

## 4. Phase 2：真实客户集成

周期：8–12 周，取决于客户 ERP 条件。

### 建设内容

- 为首个 ERP 建只读增量 Connector。
- 建立主数据映射、同步水位和数据质量告警。
- 审批后在 ERP 创建草稿单据，保存外部单号。
- 回收发货、收货、采购取消、促销销量等结果。
- 以实际结果校准预测、弹性和方案评分权重。
- 客户可配置阈值、审批流、角色和数据范围。

### 验收

- 同步失败不污染最近一次完整数据快照。
- ERP 接口超时可重试，幂等键阻止重复写单。
- 执行前数据发生关键变化时自动暂停并要求重算。
- 实际资金释放、缺货变化和报损减少可按方案归因。

## 5. Phase 3：可复制产品

周期：3–6 个月。

### 建设内容

- 多租户 SaaS 与单客户私有部署两种形态。
- Connector SDK、字段映射后台和客户沙箱。
- 评测集、Prompt/规则版本发布、灰度和回滚。
- SSO、完整审计、备份恢复、监控和告警。
- 供应商退换货、促销内容生成、采购谈判辅助等扩展。
- 经营知识库与客户策略配置，但不急于引入复杂向量检索。

### 核心产品指标

- 被发现的可干预库存资金金额。
- 建议采纳率和从发现到执行的周期。
- 预计/实际现金释放偏差。
- 近效期报损下降。
- 因调拨或停采引起的缺货增量。
- 每释放 1 万元现金的系统和执行成本。

## 6. 第一轮开发任务拆分

### Epic A：统一数据模型

- 定义 8 张首期核心表：门店、SKU、库存批次、日销售、在途采购、补货规则、风险、方案。
- 建立 Excel 模板和字段校验。
- 生成可重复的 30 店样例数据。

### Epic B：确定性分析引擎

- 周转天数、预计售罄日、临期售罄概率。
- 资金占用金额、可释放金额和采购敞口。
- 风险规则版本与单元测试。
- 调拨候选生成及安全库存校验。

### Epic C：Agent 决策闭环

- 总控状态图与 5 个专业节点。
- 工具输入输出 Schema、超时和失败处理。
- 诊断证据、方案比较和结构化解释。
- 审批前停止点及人工反馈回流。

### Epic D：产品前端

- 工作台、风险详情、方案详情、审批和现金模拟。
- Agent 运行进度、证据面板和时间线。
- 原创的 ERPNext-inspired 设计系统。
- 1024px 以上完整适配，移动端支持审批。

### Epic E：执行与效果

- 生成调拨单、促销建议和采购调整文件。
- 执行任务及状态更新。
- 预计与实际结果对比。
- 关键业务与技术指标埋点。

## 7. 建议的首期团队分工

| 角色 | 主要责任 |
|---|---|
| 产品/药店业务 | 风险口径、审批规则、Demo 故事和客户访谈 |
| 全栈前端 | Next.js 工作台、单据组件和交互体验 |
| Python/算法 | FastAPI、数据处理、预测和 OR-Tools |
| AI/Agent | LangGraph、工具协议、结构化输出和评测 |
| 兼职 DevOps/测试 | Docker、部署、日志、数据隔离和回归测试 |

小团队可以合并角色，但领域口径和算法实现必须有人分别复核。

## 8. 开发启动顺序

1. 冻结演示故事和统一字段表。
2. 先实现确定性指标及调拨求解器。
3. 将计算能力封成 Agent 工具。
4. 完成 Agent 状态图和审批停止点。
5. 用真实 API 替换当前静态页面数据。
6. 加入执行文件、追踪和结果回收。
7. 最后再增加第二种 ERP Connector 和更多自治能力。

这个顺序能保证即使模型表现不稳定，产品仍然有可演示、可核验的业务价值。
