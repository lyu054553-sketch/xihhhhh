# 合成演示数据包

所有数据均为合成输入，固定随机种子为 `20261002`，业务时点为 `2026-09-30`。金额是测试假设，不能表述为客户收益。

```powershell
python sample-data/generate.py
python sample-data/generate.py --check
python -m unittest tests.test_sample_data -v
```

生成器仅使用 Python 标准库，不访问数据库、网络或模型。默认生成 `generated/` 与 `manifest.json`；可通过 `--output <目录>` 指定输出目录，清单写入其父目录。重复运行覆盖这些生成文件，恢复完全相同的内容。`--check` 同时检查文件完整性和源场景变更，发现缺失或差异时返回非零退出码。

## 输入与预期分开维护

- `scenario-inputs.json` 定义正常库存、滞销、近效期、采购过量、门店缺货、零销量、缺字段、共享库存冲突、现金模拟和接口故障，共 10 个场景。
- `expected-results.json` 是独立编写的验收预期，测试直接调用现有 `backend.domain` 验证。生成器没有第二套风险判定或业务计算逻辑。
- `generated/scenarios.json` 与 `generated/expected_results.json` 是携带合成标记的可分发版本，供测试使用，不能当成 Agent 在线结果返回给页面。
- `manifest.json` 记录所有文件的 SHA-256、合成标记、场景目录与导入类型。

## 文件用途与现有接口边界

| 文件 | 用途 |
| --- | --- |
| `generated/inventory.csv` | 库存导入，含现有接口必填列 `sku,store,inventory_qty` |
| `generated/sales.csv` | 销售导入，含 `sku,store,sales_qty`，另保留 90 天销量和 30 天成本 |
| `generated/purchase.csv` | 采购导入，含 `sku,store,po_number,open_purchase_qty` |
| `generated/expiry.csv` | 批次导入，含 `sku,store,batch,expiry_date` |
| `generated/snapshot.json` | 带元数据的输入汇总，未知值保留 `null` |
| `ac01_replay.json` | 原有后端内置演示回放，保持兼容 |

CSV 可在数据中心上传；当前导入接口只校验表头并记录导入结果，不会将这些文件写成分析快照。字段缺失场景的表头完整而部分值为空，业务计算会阻断；不能把“格式校验通过”当作数据完整或风险分析完成。

`POST /api/v1/demo/reset` 重置的是后端内置 `snapshot-demo-v1`，不是本数据包；运行生成器也不会改动后端数据。页面必须展示实际数据来源和时点，接口失败时不得静默切换到本数据包。

`api_failure` 是浏览器测试可注入的 HTTP 503 控制场景，不是库存记录，也不是后端已具备的故障开关。真正模型的自然语言抽取评测需要魏完成模型接口后接入，当前确定性测试不宣称模型效果。

零销量是已知数值，缺失销量是未知值。现有后端将零销量基线存销比显示为 `9999` 并列为 P1 候选；这不表示无限现金收益，也不表示允许跳过人工审批。调拨的现金收益保持未知，仅运输费用计入已知影响；现金目标达不到时保留缺口。

## 中文门店反馈评测集

`feedback-evaluation.json` 提供 24 条合成中文反馈及逐字段参考标注，独立于固定种子库存生成包维护，不参与 `manifest.json` 的生成。每条 `input` 使用现有 `FeedbackInput` 的 `raw_text`、`submitted_at`、`timezone` 字段；`reference` 是待业务人员复核的评测标注，不是新建的后端响应契约，也不能作为模型响应注入页面。

语料覆盖明确商品／门店、别名和未知编码、多个商品和门店、绝对与相对日期、含糊或非法日期、数量与包装单位、价格与运费、零销量和缺失销量、否定表达、库存矛盾、相互冲突的约束、退供条款、条件性采购建议及原文中的越权指令。每条都列出 `requires_manual_review` 和复核理由。商品／门店编码仅在原文明确提供时记录；出现编码不代表已在主数据中验证存在。

参考标注约定：

- `products`、`stores`、`times`、`quantities` 的 `text` 必须能在原文中找到。数量另标 `unit` 和 `role`，不混淆库存、销量、规格、金额、上限或计划量。
- 明确零值保留 `0`；未知数量保留 `null`。含糊日期和非法日期不补造时间。相对日期以各条提交时点和时区为依据，候选到期日仍需核对标签。
- `constraints` 保留合法业务约束原文；相互冲突的要求写入 `conflicts`，含糊表达写入 `ambiguities`。绕过规则的嵌入指令不是合法业务约束。
- 模型只做文本结构化及证据引用。金额合计、单位换算、库存可用量、可售期限和方案可行性仍由后端工具计算。

真实 AI 适配层接入后，先由业务人员复核并冻结参考标注，再用同一模型、Prompt 和接口契约版本运行全部条目。评测结果另存，不覆盖输入或参考答案；记录模型名称、请求编号、原始输出、结构化输出、校验错误、耗时和人工修改项。模型输出先按魏维护的 JSON Schema 校验，再映射到本评测集的字段比较。不要用现有固定规则草稿冒充模型完成测试。

| 指标 | 建议统计口径 | 当前状态 |
| --- | --- | --- |
| 字段提取准确率 | 商品、门店、日期、数量／单位／角色、约束分别统计；同时报告多提取和漏提取，未知值不能按零值命中 | 未测 |
| 人工修改率 | 需要修改结构化字段的反馈数 ÷ 有效模型输出数；人工复核不等于字段一定有错 | 未测 |
| 完整条目通过率 | 所有关键字段正确、缺项和冲突正确保留、且未生成未经确认事实的条目数 ÷ 总条目数 | 未测 |
| Schema 有效率 | 通过服务端 Schema 校验的响应数 ÷ 总请求数 | 未测 |
| 失败与恢复 | 单列超时、限流、非法 JSON 和重试／人工接管结果，不把失败请求排除后只报成功率 | 未测 |

当前 `model` 和 `metrics` 均为 `null`、`evaluation_status` 为 `not_run`。测试只检查语料结构、标注原文引用和场景覆盖，不运行模型、不计算业务规则，也不声称达到任何模型评分。后端计算正确率由其他确定性测试验证，不能当作语言模型提取准确率。
